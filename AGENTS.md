# AGENTS.md

## Project Snapshot
- This repo builds a CloudStream3 plugin set; currently the active module is `KissKH/`.
- GitHub repository: `https://github.com/NovaCommand/CS-Custom`.
- Root Gradle scripts auto-discover plugin modules (`settings.gradle.kts`) and only package enabled ones (`status = 1` in each module `build.gradle.kts`).
- Main provider implementation lives in `KissKH/src/main/kotlin/com/byayzen/KissKH.kt`; plugin entrypoint is `KissKHPlugin.kt`.

## Branch Model — Read This First

| Branch | Purpose |
|--------|---------|
| `personal_build` | **Active development branch AND artifact host.** All source edits and all published `.cs3` / `plugins.json` files live here. |
| `master` | Legacy / documentation branch. **Do not use for active development or artifact distribution.** The repo default branch is `master` so GitHub's file-age timestamps on the repo home page reflect `master`—not `personal_build`. When a file looks "3 days old" on GitHub it is likely just the `master` view. |

**The CloudStream add-repo URL always points to `personal_build`:**
```
cloudstreamrepo://raw.githubusercontent.com/NovaCommand/CS-Custom/personal_build/repo.json
```

## CI/CD Pipeline

- Workflow file: `.github/workflows/build.yml`
- **Trigger:** push to `personal_build` (ignores `*.md`, `repo.json`, `plugins.json`, `*.cs3`, workflow files)
- **Steps:** checkout `personal_build` → JDK 21 (Temurin) → Android SDK → `./gradlew make makePluginsJson` → patch `builds` → `personal_build` in auto-generated `plugins.json` URLs → commit & push `KissKH.cs3` + `plugins.json` back to `personal_build`
- **The root `KissKH.cs3` and `plugins.json` are always machine-generated by CI; never edit them by hand.**
- After every successful run the file hash and size in `plugins.json` are updated automatically. Verify via:
  ```
  https://raw.githubusercontent.com/NovaCommand/CS-Custom/personal_build/plugins.json
  ```

## Architecture You Need First
- **Build layer:** root `build.gradle.kts` defines common Android/Kotlin config and custom tasks; module scripts provide plugin metadata via `cloudstream { ... }`.
- **Plugin registration:** `KissKHPlugin.kt` uses `@CloudstreamPlugin` and registers providers in `load(context: Context)` — the `context` parameter is **required**; omitting it silently breaks provider registration at runtime.
- **Provider flow (`KissKH.kt`):**
  1. home/search endpoints build UI cards,
  2. `load(url)` fetches title details and episode list,
  3. `loadLinks(...)` resolves streams and subtitles for playback.
- **Subtitle crypto boundary:** `SubDecryptor.kt` handles AES/CBC decryption used by `KissKH.kt` when subtitle URLs are encrypted `.txt` payloads.
- **Repo distribution metadata:** `repo.json` + `plugins.json` point to published `.cs3` artifacts and plugin index URLs on `personal_build`.

## Critical Workflows (Windows PowerShell)
- Build everything enabled:
  - `./gradlew.bat build`
- Build only active plugins via custom task:
  - `./gradlew.bat derle`
- Build only the KissKH module:
  - `./gradlew.bat :KissKH:build`
- Clean artifacts:
  - `./gradlew.bat clean`
- Use `--info` (or `--stacktrace`) when debugging Gradle/plugin packaging issues.
- **Local builds require Java on PATH.** Do NOT add `org.gradle.java.home` to `gradle.properties` with a machine-specific path—it will break CI on Linux and any other developer machine.

## Known Pitfalls — Do Not Repeat

1. **Never set `org.gradle.java.home` in `gradle.properties` to a machine-specific path.**
   The property was previously set to `C:\Users\DevBox\...`, which broke CI on the Linux GitHub Actions runner. Leave it unset; let the runner/developer use their own JDK.

2. **Never point `build.yml` triggers at `master`/`main` for artifact builds.**
   All source and artifact work happens on `personal_build`. A trigger on `master` will never fire for normal development.

3. **Never create a separate `builds` branch for artifacts in this repo.**
   The upstream repo `Kraptor123/Cs-Karma` uses a `builds` branch, but this fork does not. Artifacts are committed directly to `personal_build`. Attempting to checkout a non-existent `builds` branch in CI causes an immediate job failure.

4. **Never commit a pre-built `.cs3` after making source changes without rebuilding.**
   CI is the only correct way to publish artifacts. A stale binary can contain the wrong class signatures (e.g., missing `context` parameter in `Plugin.load()`) that are invisible at commit time but break plugin selection at runtime inside CloudStream.

5. **The `setRepo` call in `build.gradle.kts` must produce a full HTTPS URL.**
   The CloudStream Gradle plugin passes this URL into generated metadata. The correct pattern is:
   ```kotlin
   setRepo(System.getenv("GITHUB_REPOSITORY")?.let { "https://github.com/$it" } ?: "https://github.com/NovaCommand/CS-Custom")
   ```
   Using just `owner/repo` (the raw `GITHUB_REPOSITORY` value) or the upstream fork URL will generate wrong download paths in `plugins.json`.

6. **The `build.yml` auto-generated `plugins.json` hardcodes `builds` as the branch name in artifact URLs.**
   A `sed` step in the workflow patches this to `personal_build` before committing. Do not remove that step.

7. **GitHub's file-age label on the repo home page reflects the default branch (`master`), not `personal_build`.**
   If `KissKH.cs3` shows "3 days ago" on the GitHub UI but the latest CI run succeeded, check `personal_build` directly—the artifact is almost certainly fresh there.

## Project-Specific Patterns To Follow
- Keep provider classes extending `MainAPI` with the CloudStream contract methods (`getMainPage`, `search`, `load`, `loadLinks`). See `KissKH.kt`.
- Keep plugin metadata in module `cloudstream { ... }` block aligned with code behavior (language, status, tvTypes, authors). See `KissKH/build.gradle.kts`.
- JSON mapping is done with Jackson annotations (`@JsonProperty`) in local data classes near usage (`KissKH.kt`), not in a separate model package.
- Network calls frequently combine Jsoup + `app.get(...)` and should preserve existing headers/cookies patterns in `KissKH.kt`.
- Subtitles may require decryption before emission; reuse `SubDecryptor` instead of duplicating crypto code.

## Safe Change Strategy For Agents
- When touching scraping logic, validate all three paths: home cards, details/episodes, and `loadLinks` extraction.
- When changing build metadata (`status`, `version`, URLs), also verify generated plugin index files remain consistent (`plugins.json`, `repo.json`).
- Prefer minimal, localized edits in `KissKH.kt`; this file mixes endpoint contracts, parsing, and playback extraction in one provider class.
- After any source change, push to `personal_build` and confirm the GitHub Actions `Build` workflow completes with `conclusion=success` before considering the plugin published.
- To verify the live artifact, check: `https://raw.githubusercontent.com/NovaCommand/CS-Custom/personal_build/plugins.json` — the `fileHash` and `fileSize` must match the rebuilt `.cs3`.
